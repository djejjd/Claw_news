## 1. 背景

仓库目前没有前端工程。公共 API 已提供稳定只读 DTO，但浏览器端需要独立、可测试且不改变后端的构建基础。

## 2. 目标

建立 Vue 3 + TypeScript 前端工程，提供开发、构建、类型检查、单元测试和浏览器测试的最小基础；只建立骨架和可注入 API client，不交付具体日报或新闻业务页面。

## 3. 前置依赖

- `v1.1.0` 公共 API 已发布；
- 《公共网站前端设计》已批准并冻结路由、开发 API 地址和测试运行方式；
- Node.js `22.x`、npm `10.x`、`package-lock.json` 与 Chromium Playwright 运行方式已冻结。

## 4. 输入与输出契约

输入为三条已批准公共 API 的 DTO 与错误响应。输出为独立构建的静态前端应用和隔离真实 API E2E 服务：前端经 Vite `/api` 代理访问显式本地目标；测试服务以临时 SQLite 发布库和既有公共路由提供种子数据，不导入 `app.main`。client 不携带凭证、不访问非公共路由、不提供模拟数据 fallback。构建失败、类型错误和测试失败均返回非零退出码。

## 5. 修改范围与接口变更表

| 变更 | 输入/返回 | 副作用 | 兼容性 | 测试 |
|---|---|---|---|---|
| 新增前端工程 | 浏览器加载静态资源 | 仅本地构建产物 | 不修改 FastAPI | 构建、类型检查、基础渲染 |
| 新增公共 API client 基础 | API base URL -> `fetch` 响应/显式错误 | 只读 HTTP | 不改变 API 参数或 DTO | client 成功与网络失败测试 |
| 新增隔离 E2E API 服务 | 固定 SQLite 种子 -> 既有公共路由 HTTP 响应 | 临时文件与端口 | 不启动 scheduler 或生产流水线 | 成功、空、503、网络断开 |
| 新增前端 CI | Node 22 + `npm ci` -> 前端检查 | CI 临时浏览器安装 | 保持 Python CI | lint、类型、单元、构建、E2E |
| 保持公共 API | 原有路径、DTO、错误码 | 无 | 完全保持 | 契约 fixture 验证 |

## 6. 禁止事项

- 不修改后端、公共 API、数据库或 Python 依赖；
- 不引入登录、Cookie、token、订阅、后台或生产部署；
- 不写死服务器地址、密钥或真实内容；
- 不以 mock 数据作为页面成功状态的运行时替代。
- 不导入 `app.main`、不启动 APScheduler、采集、LLM、投递或项目 `data/` 写入；
- 不改动生产 CI 的 Python 版本、FastAPI 启动方式或部署配置。

## 7. 执行要求

先为工程启动、API client 正常/失败路径、测试服务种子与错误路径写失败测试，再完成最小实现。所有注释使用中文；配置区分开发和测试，不提交 `.env`。固定 Node `22.x`、npm `10.x`、`package-lock.json` 和 Chromium 浏览器版本策略；CI 与根 Makefile 必须执行同一组前端命令。

## 8. 实施步骤

1. 新增构建、类型检查、单元、E2E 和 CI 脚本的失败验证。
2. 新增 API base URL、client 错误转换、SQLite 种子和公共路由错误响应的失败测试。
3. 创建 Vue、TypeScript、路由、单测、Playwright、Vite 代理及隔离 API 服务。
4. 在 Makefile 和 CI 接入 `npm ci`、lint、类型检查、单元、构建和 Chromium E2E。
5. 运行精确检查、完整前端检查和 diff 审核。

## 9. 验收标准

1. 前端可独立安装、开发启动、构建和类型检查。
2. API client 只允许公共 API base URL，并将非成功响应和网络故障转换为可显示的错误状态。
3. 没有模拟内容、认证凭证或生产部署配置。
4. 浏览器测试经 Vite 代理访问临时 SQLite 发布库上的实际公共路由，且不启动 scheduler 或生产流水线。
5. CI 对每个 PR 执行固定 Node/npm、lint、类型检查、单元、构建和 Chromium E2E。

## 10. 检查命令

`npm ci`；`npm run lint`；`npm run typecheck`；`npm run test`；`npm run build`；`npm run e2e`；根目录 `make frontend-check`（lint、类型检查、单元测试、构建）；`make frontend-e2e`（仅 E2E）；`make check-public`。CI 先执行 `npm ci` 与 `npx playwright install --with-deps chromium`，再调用这两个 Make 目标。

## 11. 交付前自检

确认只修改 `frontend/**`；正常、配置缺失、网络失败和非 2xx 响应均有测试；无密钥、服务器地址或运行时 mock fallback；完整 diff 已经主审核。

## 12. 交付格式

按仓库固定交付格式列出完成内容、文件、契约对应、检查结果、测试、未完成项、风险、冲突、范围外改动和主审核重点。
