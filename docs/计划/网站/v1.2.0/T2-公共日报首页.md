## 1. 背景

公共日报是未登录用户的首个浏览入口。它必须展示已定版的公共日报，不能直接读取内部 `Digest`、候选池或运行审计。

## 2. 目标

交付默认当天日报页面，展示日报日期、判断、排序日报项、GitHub 推荐及文章原文跳转，并提供加载、日报不存在和服务不可用状态。

## 3. 前置依赖

- T1 已完成并经审核；
- 《公共网站前端设计》第 3-5 节已批准并冻结；
- `/api/public/digests?date=` 的 DTO、`404/digest_not_found` 和 `503/publication_unavailable` 保持 v1.1.0 契约。

## 4. 输入与输出契约

输入为 `DigestPublic` 或公开错误 DTO。输出为浏览器页面：默认请求不携带 `date` 查询参数，由 API 选择当天日报；成功时按 API `position` 展示，空 `summary` 不伪造内容；`404` 显示无日报状态，`503` 与网络失败显示可重试失败状态。仅 `original_url` 可作为外部跳转目标。

## 5. 修改范围与接口变更表

| 变更 | 输入/返回 | 副作用 | 兼容性 | 测试 |
|---|---|---|---|---|
| 新增日报页面 | `DigestPublic` -> 可访问页面 | GET 请求 | 不改 API | 成功、加载、404、503、网络失败 |
| 新增日报展示组件 | `DigestItemPublic`/项目推荐 -> 语义化内容 | 无 | 不序列化内部字段 | 排序、空摘要、外链 |
| 保持 API | 查询参数及响应不变 | 无 | 完全保持 | fixture 契约测试 |

## 6. 禁止事项

- 不增加日期写入、登录、订阅、收藏或新闻筛选；
- 不把内部评分、`relevance` 或候选字段展示到页面；
- 不修改 T1 的构建和浏览器测试配置；
- 不把 404、503 或网络失败伪装为成功空页面。

## 7. 执行要求

测试先行覆盖成功、加载、404、503、网络异常、空摘要和固定排序。外链必须使用 API 返回 URL，保持安全的浏览器跳转属性；复杂错误分支使用中文注释说明状态语义。

## 8. 实施步骤

1. 为日报成功、错误和加载状态添加失败测试。
2. 为排序、空摘要与外链添加失败测试。
3. 实现 DTO 映射、页面和可重试失败状态。
4. 运行精确测试和浏览器路径测试，提交主审核。

## 9. 验收标准

1. 未登录用户可从真实 `DigestPublic` 浏览当天日报。
2. 报项与项目推荐顺序同 API，公开字段完整且内部字段不出现。
3. 404、503 和网络错误可区分，且加载状态不会残留旧日报。
4. 原文链接正确跳转，页面在窄屏仍可读。

运行 T1 规定的类型检查、日报组件单元测试、日报浏览器测试、前端构建和 `make check-public`。
