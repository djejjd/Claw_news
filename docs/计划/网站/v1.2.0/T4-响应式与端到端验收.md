## 1. 背景

日报与新闻流的功能完成不等于公共站点可用。需要验证窄屏排版、状态切换和真实 API 浏览链路，防止只在桌面或 mock 响应中成立。

## 2. 目标

完成公共网站的响应式收口和端到端核心路径验收，并将版本退出条件的可复现检查结果记录到版本方案。

## 3. 前置依赖

- T2、T3 均已完成并通过主审核；
- 《公共网站前端设计》第 5、7、8 节已批准并冻结；
- T1 的隔离 E2E API 服务可提供固定已发布 SQLite 种子和实际公共路由；
- 浏览器测试工具和视口基线已由 T1 锁定。

## 4. 输入与输出契约

输入为完成的公共前端和 T1 的隔离公共路由 API 服务。输出为桌面与移动视口下可访问的日报、新闻流和来源筛选路径；任何 API 失败、空内容或加载中均保持可理解状态且不发生布局重叠。验收记录必须使用固定 SQLite 种子、Vite 代理和实际 `app.publication.routes.router`，不能以浏览器 mock 替代。

## 5. 修改范围与接口变更表

| 变更 | 输入/返回 | 副作用 | 兼容性 | 测试 |
|---|---|---|---|---|
| 响应式样式收口 | 视口变化 -> 稳定可读布局 | 无 | 不改变 API | 桌面/移动截图与像素检查 |
| 核心 E2E | SQLite 种子上的实际公共路由 -> 浏览路径 | 只读 GET | 不触发 scheduler、采集或生产写入 | 日报、分页、筛选、错误路径 |
| 验收记录 | 命令结果 -> 版本退出证据 | 仅文档 | 不发布/部署 | 记录真实 API 与 fixture 结果 |
| 保持 API | 路径、参数、DTO、错误不变 | 无 | 完全保持 | 契约回归 |

## 6. 禁止事项

- 不为通过 E2E 而修改 API、发布库或生产配置；
- 不将浏览器 mock 或静态 fixture 结果描述为真实 API 验收；
- 不新增账户、订阅、后台、部署、缓存或监控；
- 不用隐藏错误、固定高度截断内容或静默回退掩盖布局和失败问题。

## 7. 执行要求

先新增会失败的窄屏、加载/错误切换和端到端测试，再调整最小实现。至少覆盖桌面与移动各一个固定视口；截图检查文本溢出、重叠、不可见控件和外链可用性。对验收中不能运行的真实 API 项登记唯一待办、前置条件与关闭条件。

## 8. 实施步骤

1. 编写日报、新闻分页、来源筛选和失败状态的浏览器失败测试。
2. 编写桌面/移动视口的截图或 DOM 可见性失败测试。
3. 修复响应式布局和状态切换问题。
4. 运行固定 SQLite 种子、隔离公共路由和 Vite 代理的 E2E，记录命令和结果；执行完整前端检查和主审核。

## 9. 验收标准

1. 桌面和移动端均可完成日报浏览、新闻翻页和来源筛选。
2. 所有状态文本和交互控件可见、可操作且不重叠或溢出。
3. E2E 验证正常、空、404/503 或网络失败路径；筛选分页具有连续变化序列断言。
4. E2E 指向临时 SQLite 发布库上的实际公共路由；启动过程不导入 `app.main`，且断言不启动 scheduler 或生产流水线。无法验证时按唯一待办登记，不能声称版本完成。
5. 构建、类型检查、单元测试、浏览器测试和公开边界检查全部通过。

## 10. 检查命令

运行锁定的前端格式、类型、单元、构建和浏览器命令，以及 `make check-public`；真实 API 验收命令和结果需记录在版本方案。

## 11. 交付前自检

确认只修改允许路径；桌面/移动、正常/空/加载/失败、两次筛选或分页变化和真实 API 路径均有证据；未验证项已登记；无部署、API 或后端变更；已审核 diff。

## 12. 交付格式

按仓库固定交付格式列出完成内容、文件、契约对应、检查结果、测试、未完成项、风险、冲突、范围外改动和主审核重点。
