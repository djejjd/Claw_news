## 1. 背景

`v1.0.0` 已将过滤后允许公开的文章、日报、日报项、GitHub 推荐和来源写入 PostgreSQL 发布库，并保持内容发布、消息投递和本地运行审计相互隔离。网站后续需要稳定的只读公共接口，但当前 FastAPI 仅提供服务状态和手动运行入口，尚未向未登录客户端暴露发布内容。

本版本只在发布库上建立公共读取层，为 `v1.2.0` Vue 3 + TypeScript 前端提供真实契约；不得将内部候选池、运行审计或采集流程作为查询来源。

## 2. 目标

提供以下稳定、未登录可调用的只读接口：

- `GET /api/public/digests?date=`；
- `GET /api/public/articles?date=&source=&page=`；
- `GET /api/public/sources`。

接口只返回 `published` 内容，按配置时区解释自然日，新闻流采用稳定排序和服务端受控分页；同时完成最近 10 天内容的过期清理、字段隔离、异常响应和数据库查询验证。

## 3. 前置依赖

- `Article`、`Digest`、`DigestItem`、`DigestGitHubProject`、`Source` 和 `SourceFeed` 的迁移及发布写入已存在；
- 发布文章的最终分类只能是 `ai`、`tool`、`game`、`digital`，`device` 仅为输入兼容别名；
- 内容状态为 `published`、`hidden`、`expired`，公共读取只接受 `published`；
- 数据库存储时间为带时区 UTC，`config.tz` 是自然日和保留窗口的唯一解释依据；
- 发布库未启用或不可用时，API 不得回退读取 JSON、候选池或外部来源。

## 4. 输入与输出契约

公共 HTTP、字段、错误、时间、排序、分页、来源可见性和清理的唯一设计来源为[《公共内容 API 设计》](../../架构/公共内容API设计.md)。本计划下文仅摘录实施约束以便拆分任务，不新增或覆盖该设计；任务包不得改变接口语义。

输入：发布库中的已发布内容、`AppConfig` 中的发布库连接与 `tz`、以及公共查询参数 `date`、`source`、`page`、`page_size`。

输出：

- `date` 仅接受 `YYYY-MM-DD`。日报未传 `date` 时取 `config.tz` 的当天；新闻流未传 `date` 时返回当地最近 10 个自然日，传入时按当地自然日的 `fetched_at` 筛选。窗口外的有效日期返回空列表，日报不存在返回 `404`；
- 日报接口返回指定自然日的单一公共日报、其排序后的公开日报项和可公开的 GitHub 推荐；日报项使用文章公开字段及 `position`、`core_summary`、`importance`、`trend`、`topic_label`；
- 新闻流返回公开文章、来源摘要和 `{items, page, page_size, total}` 分页元数据；`source` 使用稳定来源名，未知或无公开内容的来源返回空列表；
- `page` 默认 `1` 且最小为 `1`，`page_size` 默认 `20`、最小为 `1`、最大为 `50`；超过末页返回空 `items` 并保留请求页和总数；
- 来源接口按展示名、稳定来源名确定排序，返回当前 10 天内至少关联一条 `published` 文章的来源；`is_enabled` 只影响后续采集，不隐藏既有公开文章所属来源。响应仅含 `name`、`display_name`、`site_url`，不返回 feed 地址、策略、健康错误或订阅默认值；
- 时间字段均为 ISO 8601 且保留时区信息；新闻流按 `published_at`（缺失时 `fetched_at`）倒序、稳定 `id` 并列排序；无来源摘要时 `summary` 返回空字符串；
- 文章公开字段仅为 `id`、`title`、`original_url`、`category`、`topic`、`summary`、`published_at`、`fetched_at` 和嵌套来源的 `name`、`display_name`、`site_url`；日报公开字段仅为 `date`、`version`、`published_at`、`daily_judgement`、公开日报项和 GitHub 推荐的 `position`、`full_name`、`recommendation`；
- `visibility`、`canonical_key`、`topic_confidence`、`relevance`、`final_score`、来源 feed、内部评分、运行错误、重试状态和所有内部候选字段不得出现在响应中；
- 参数格式或分页范围非法时统一返回 `422` 和 `{"detail": {"code": "invalid_request", "message": "..."}}`；日报不存在时返回 `404` 和 `{"detail": {"code": "digest_not_found", "message": "..."}}`；发布库未启用或不可用时返回 `503` 和 `{"detail": {"code": "publication_unavailable", "message": "..."}}`，不得返回数据库异常原文。

以上响应结构和错误语义为本任务包的实施契约。T1 必须先以响应模型和失败契约测试固定它们，再开始路由实现；不得以 FastAPI 默认校验响应或临时默认值替代。

## 5. 修改范围

1. 为发布库新增公共只读查询接口和公开 DTO/响应模型，禁止直接序列化 ORM 或内部候选对象。
2. 将公共 API 路由注册到现有 FastAPI 应用，读取配置的发布库连接，不新增采集、LLM 或投递依赖。
3. 实现日报、新闻流和来源列表三组查询，以及稳定排序、日期/来源过滤和受控分页。
4. 在既有高频 ingest 调度任务中增加受控发布库清理：每次任务结束后，仅在发布库启用时按 `config.tz` 清理；第 11 天先将文章标记为 `expired`，再删除过期内容的日报关联，最后删除文章。清理失败只记录发布库降级，不影响采集、消息投递或查询请求。
5. 覆盖 API 契约、参数校验、异常响应、字段脱敏、查询无副作用、数据库排序与清理边界测试，并同步正式文档入口。

## 6. 禁止事项

- 不增加 Vue、静态页面、浏览器路由或模拟数据；
- 不增加登录、Session、邀请、订阅写入、管理员接口或角色校验；
- 不修改采集、筛选、摘要、发布、消息投递、内容 outbox 或 JSON 审计语义；
- 不在查询请求中触发采集、LLM、消息推送、外部 HTTP 请求或历史 JSON 回填；
- 不将 `hidden`、`expired`、未发布内容、内部评分/相关性、错误信息、feed 地址、密钥或认证 URL 暴露给客户端；
- 不为 PostgreSQL 生产 Compose、反代、CORS 或部署引入配置，这些留至后续版本；
- 不在本版本修改 `pyproject.toml` 正式版本、`CHANGELOG.md` 或创建 tag。

## 7. 执行要求

- 每项行为测试先行：先新增预期失败的查询/API 测试，再写最小实现；
- 公共响应使用显式字段白名单；新增 ORM 字段不会自动进入 API；
- 所有读取显式限制 `published`，日期边界通过 `config.tz` 转换为 UTC 查询范围；
- 分页排序必须完全确定，禁止以数据库默认顺序作为契约；页码和页大小由服务端校验并限制上限；
- 清理过程应可重复执行；测试必须覆盖相邻自然日、两次运行及 `expired` 标记、日报关联、文章删除的顺序；
- 查询路径不允许写入文章、日报、来源、JSON 状态或投递状态；清理固定由既有高频 ingest 调度任务在任务结束后触发，不能由单次公共查询隐式触发；
- 公共 API 对参数错误、日报不存在和发布库不可用必须使用本计划定义的统一错误结构，禁止泄露 FastAPI/Pydantic、SQLAlchemy 或数据库驱动的内部详情；
- 每个任务级 commit 前必须由主审核 AI 审查完整 `git diff`；未经用户批准不得 push、合并、部署或创建 tag。

## 9. 验收标准

1. 未登录客户端可通过三条公共接口读取公共日报、最近 10 天新闻流和来源列表，不依赖候选池或 JSON 状态文件。
2. `hidden`、`expired`、未发布文章及关联日报项不会通过任何公共接口返回。
3. 所有日期依据 `config.tz` 解释，新闻流按约定时间字段和 `id` 稳定排序；翻页无重复、无遗漏和无不确定顺序。
4. 缺省日期、非法日期、非法分页、日报不存在、窗口外日期和未知来源的响应符合本计划定义的状态码和 JSON 契约。
5. 第 11 天过期清理遵循 `expired` 标记、日报关联、文章删除的顺序；连续执行至少两次不误删保留窗口内内容，也不产生异常或计数失真。
6. 响应不包含内部候选、评分、相关性、错误、重试、来源 feed/策略、认证 URL 或其他非公开字段。
7. 查询请求不触发采集、LLM、消息投递、外部 HTTP 或任何持久化写入；发布库不可用时返回 `503/publication_unavailable`，不以 JSON 或候选池静默回退。
8. 全部新增行为具备正常、边界、降级和失败路径测试，且对字段隔离和状态/清理逻辑满足仓库整改复审门禁。
