## 1. 背景

现有排障文档不足以覆盖持续巡检、恢复演练、危险操作和异常闭环。

## 2. 目标

建立日、周、月、季度维护任务及故障、恢复、密钥轮换和升级记录的正式手册。

## 3. 前置依赖

T1 已完成观测、备份与恢复基础；T3 状态须在文档中如实标注。

## 4. 输入与输出契约

输出为可执行维护手册，逐项列明频率、责任角色、命令、预期证据、异常升级和关闭条件。

## 5. 修改范围

仅改允许的运维/计划文档；不改变服务、存储、调度或保留策略。

## 6. 禁止事项

不得把清空数据、恢复快照、生产发布或凭据轮换写成无授权的日常命令；不得记录私有信息。

## 7. 执行要求

区分只读、可逆和破坏性操作；破坏性操作必须包含授权、快照、影响范围和恢复验证。

## 8. 实施步骤

1. 核对 T1 状态、回放和运行命令。
2. 编写周期任务、升级流程和恢复记录要求。
3. 复核与排障文档一致性，并将入口链接需求交给 T5 汇总。

## 9. 验收标准

新维护人员能完成健康、质量、渠道、日志、卷和重试检查；危险操作有明确约束；未验证项可追溯。

## 10. 检查命令

```bash
rg -n "每日|每周|每月|恢复|快照|升级" docs/运维/维护.md docs/运维/排障.md
make check-public
```

## 11. 交付前自检

核对命令与实现一致、无私有信息、T3 状态真实、危险操作有快照和验证。

## 12. 交付格式

按固定格式，单列人工维护项、遗留待办和风险。
