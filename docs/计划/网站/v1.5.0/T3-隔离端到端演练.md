## 1. 背景

现有 `dry-run` 不验证服务模式的真实采集、摘要和渠道投递；生产发布接口会写入正式状态。

## 2. 目标

实现唯一的 one-shot 隔离演练命令 `python -m app.acceptance.run`，完成真实采集、摘要和验收渠道投递；该命令不启动 FastAPI、HTTP 服务或 APScheduler，并拒绝可验证的生产状态根、生产渠道变量和不完整验收配置。数据库及凭据实际身份由部署门禁人工核验，程序不得伪称可自动识别。

## 3. 前置依赖

T1 的持久化与部署边界已验证；运维已准备独立验收卷、数据库和渠道凭据。

## 4. 输入与输出契约

输入为 `RUN_MODE=acceptance`、绝对 `STATE_ROOT`/`PRODUCTION_STATE_ROOT`、验收 `.env` 与设计 3.1 的 `ACCEPTANCE_*` 命名空间；部署前由运维核验独立 secret 引用、数据库身份和验收渠道。验收模式只读取白名单 `ACCEPTANCE_*`：验收 LLM、完整的一组渠道、必填 `ACCEPTANCE_PUBLICATION_DATABASE_URL` 及所有映射后的应用/来源控制变量；同名进程环境覆盖 `.env.acceptance`，未设置时使用设计默认值，绝不回退标准变量。Alembic 在验收模式只读取 `ACCEPTANCE_PUBLICATION_DATABASE_URL`，不接受标准数据库变量。输出为 one-shot 命令、验收 Compose/配置模板及测试。所有列举的状态存储、outbox、指标、GitHub 快照和健康读取必须从 `STATE_ROOT` 派生，默认生产行为、调度和接口保持不变。

## 5. 修改范围

仅修改允许路径；新增环境变量、错误和审计字段必须以设计契约和测试固定。

## 6. 禁止事项

不得复用生产渠道、卷、数据库或状态；不得自动运行真实演练；不得复制或回写生产状态。不得读取项目根 `.env`、标准生产变量或生产 Compose。不得尝试从 token、webhook URL、DSN、主机名或任意环境变量声明自行推断凭据/数据库归属；差异以独立 secret 引用/版本或指纹、验收数据库身份和验收群消息的人工核验证据为准，值不得进入代码、日志或文档。

## 7. 执行要求

测试先行；验收配置测试必须覆盖完整白名单、生产/验收命名空间、进程环境覆盖 `.env.acceptance`、标准变量绝不回退、必填/成组/空值与至少一组验收渠道。直接读取的 RSS、来源可选性、代理和 GitHub 预算必须使用相应 `ACCEPTANCE_*` 变量；Alembic 测试必须证明验收迁移只使用 `ACCEPTANCE_PUBLICATION_DATABASE_URL` 且标准数据库变量为空。每条拒绝规则同时覆盖生产变体与合法验收相邻值。验收 Compose 必须不映射生产端口、不开启自动重启调度；服务启动测试断言 scheduler job 数为零，未经 one-shot 命令时零写入、零投递。连续两次演练逐步断言验收状态变化，并枚举设计列出的全部状态产物，断言生产状态目录的内容和元数据不变。

## 8. 实施步骤

1. 为 `RUN_MODE`、完整白名单、标准/验收变量混用、进程环境覆盖 `.env.acceptance`、标准变量不回退、验收 LLM、渠道成组、验收数据库、验收 Alembic 数据库变量、相对/空/相同状态根写失败测试；将数据库/secret 身份核验列为部署门禁人工证据，不伪造自动化判断。
2. 实现 `RUN_MODE`、验收变量命名空间及直接读取来源控制变量的映射、验收 Alembic 数据库变量、`STATE_ROOT` 全链路注入、所有列举存储入口的绝对路径传递、无 scheduler 的 one-shot 命令及隔离 Compose/模板。
3. 补齐 scheduler 为零、未经命令零副作用、正常/失败/连续运行、全状态产物和外部渠道人工验收。

## 9. 验收标准

one-shot 演练只写验收状态；非 acceptance 模式、标准/验收变量混用、非法/相同状态根、不完整验收配置及使用标准数据库变量的验收 Alembic 全部拒绝；验收 Compose 与命令均不启动 scheduler；两次演练可追溯；设计列出的所有生产状态产物内容和元数据不变；独立 secret/数据库身份及验收渠道有人工核验证据；生产调度与接口回归通过。

## 12. 交付格式

按固定格式，单列隔离反向测试、人工渠道证据和残留风险。
