## 1. 背景

`v1.5.0` 需要先建立网站和投递服务共用的可部署、可恢复、可观测基础。

## 2. 目标

交付单实例 Compose、反代、持久卷、数据库迁移与备份恢复、HTTPS/Cookie/端口安全、日志/资源/发布失败观测与告警基线。

## 3. 前置依赖

网站功能验收完成，服务器资源评估和生产域名/证书方案已确认。

## 4. 输入与输出契约

输入为已批准设计和服务器运行约束；输出为不含密钥的部署资产及可验证备份恢复流程。生产数据持久化、单实例和单调度来源保持不变。

## 5. 修改范围

仅修改元信息允许路径；不改变内容选择、推送、公开 API 或认证语义。

## 6. 禁止事项

不部署到生产；不提交密钥、真实主机信息或生产数据；不引入多实例写入。

## 7. 执行要求

备份与恢复测试必须成对验证：在干净数据库恢复后执行迁移和应用读取，断言核心表计数或校验和与备份一致。迁移失败不得切换流量；反代测试须验证 HTTPS、生产 Cookie 标志和应用/数据库不对公网暴露。监控/告警必须区分正常、降级和失败；复杂恢复与持久化路径使用中文定向注释。

## 8. 实施步骤

1. 先写部署、卷、备份恢复与告警失败测试。
2. 实现 Compose/反代/备份/观测资产。
3. 在隔离环境验证启动、恢复和告警。

## 9. 验收标准

单实例可启动，持久卷不丢失；迁移可执行且失败不切换流量；备份可恢复到干净数据库并通过应用读取及计数/校验和核对；HTTPS、Cookie 标志和端口暴露符合生产边界；健康、资源和发布失败可见；未泄露敏感配置。

## 10. 检查命令

```bash
./venv/bin/pytest tests/test_deploy_*.py -v
make test
make lint
./venv/bin/ruff format --check .
make check-public
```

## 11. 交付前自检

核对持久化、恢复、单调度、秘密边界和完整 diff；生产验证未执行时明确登记。

## 12. 交付格式

按仓库固定交付格式，重点说明恢复证据、人工环境验证和残留风险。
