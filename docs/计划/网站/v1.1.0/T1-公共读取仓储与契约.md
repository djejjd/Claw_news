## 1. 背景

发布库已有写入模型，但没有可复用的公共读取接口。若路由直接访问 ORM，新增内部列时容易泄露数据，也会让日期、排序和可见性规则分散在多个端点。

## 2. 目标

建立公共读取仓储、公开 DTO 和统一错误响应基础，作为 T2-T4 唯一的数据访问与序列化边界。

## 3. 前置依赖

- `v1.0.0` 的发布库模型和迁移已完成；
- `articles.visibility` 的公共可见值仅为 `published`；
- 版本总览第 4 节的日期、分页、字段白名单和错误响应已批准。

## 4. 输入与输出契约

输入：SQLAlchemy 发布库会话、`config.tz`、已验证的本地自然日和分页参数。

输出：

- 仓储只返回 `published` 文章及其公共所需关联数据；
- 提供按自然日查询日报、按日期/来源查询文章、查询当前窗口可展示来源的读取方法；
- 文章、日报、日报项、GitHub 推荐、来源和错误均使用显式 DTO；
- 定义 `invalid_request`、`digest_not_found`、`publication_unavailable` 的统一 `{detail: {code, message}}` 响应模型；
- 不提供写入、清理、ORM 直出或候选池读取接口。

## 5. 修改范围

1. 在 `PublicationStore` 或其专属只读协作者中增加公共查询方法。
2. 新增公开 DTO、分页 DTO 和错误 DTO，字段严格遵循版本总览白名单。
3. 将 `config.tz` 的当地自然日转换为 UTC 查询边界，并封装稳定排序规则。
4. 为未启用或不可用的发布库定义可由路由转换为 `503` 的领域错误。

## 6. 禁止事项

- 不注册 HTTP 路由，不修改 `app/main.py`；
- 不执行清理或其他写入；
- 不返回 `canonical_key`、`visibility`、评分、`relevance`、feed 或运行错误；
- 不以本地 JSON、候选池或外部请求替代数据库读取。

## 7. 执行要求

- 先写失败测试，再实现最小查询和 DTO；
- 所有查询显式带 `visibility == published` 条件；
- 时间边界、稳定排序和字段白名单必须由单元测试断言具体值；
- 测试同时覆盖 `hidden`/`expired` 应拒绝和同词根但合法的公开字段应保留，防止脱敏规则误伤；
- 复杂时区和异常转换路径补充中文定向注释。

## 8. 实施步骤

1. 新增 DTO 与领域错误的失败测试。
2. 新增日期窗口、排序和公共字段白名单的失败测试。
3. 实现读取仓储和 DTO 映射。
4. 运行精确测试、检查完整 diff，提交主审核。

## 9. 验收标准

1. 读取方法不会返回非 `published` 内容或内部字段。
2. 相同时间文章按 `id` 具有确定顺序。
3. 时区边界不会将相邻当地自然日的文章混入结果。
4. 数据库不可用可被调用方转换为统一错误，且不泄露连接串或驱动详情。
5. 读取调用不产生任何数据写入。
