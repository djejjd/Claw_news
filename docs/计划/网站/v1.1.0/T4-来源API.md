## 1. 背景

新闻流筛选需要稳定来源名和展示信息。`sources` 与 `source_feeds` 中同时包含公开展示数据与采集、策略、健康和订阅内部数据，必须建立严格读取边界。

## 2. 目标

实现 `GET /api/public/sources`，只列出当前公共新闻窗口可供浏览器筛选的来源。

## 3. 前置依赖

- T1 的来源 DTO 白名单与读取边界已完成；
- T3 的 10 天窗口和清理语义已完成；
- 来源稳定名、展示名和 feed 地址分离的模型契约保持不变。

## 4. 输入与输出契约

输入：当前保留窗口内的 `published` 文章及其关联来源。

输出：

- `200` 返回按 `display_name`、`name` 升序稳定排序的来源列表；
- 每项仅含 `name`、`display_name`、`site_url`；
- 仅包含窗口内至少有一篇 `published` 文章的来源；来源 `is_enabled` 不作为历史公开内容的隐藏条件；
- 无来源时返回 `[]`；发布库未启用或不可用时返回 `503/publication_unavailable`；
- 不返回 `default_category`、订阅默认值、feed URL、采集器、策略、健康时间、失败计数或错误摘要。

## 5. 修改范围

1. 增加来源公共读取查询和端点。
2. 复用 T1 DTO、错误模型和 T3 保留窗口定义。
3. 增加字段脱敏、排序、窗口和数据库不可用测试。

## 6. 禁止事项

- 不实现来源新增、修改、启停、测试或任何管理写操作；
- 不将 `SourceFeed` 或来源健康详情写入响应；
- 不因来源禁用而改变已发布文章的可见性；
- 不修改采集来源注册或来源策略。

## 7. 执行要求

- 先写失败测试，再添加查询和路由；
- 测试同时断言应隐藏的 feed/健康字段和应保留的合法展示名；
- 同一来源多篇文章不能在列表中重复；
- 验证空列表、排序并列、窗口外文章和发布库故障。

## 8. 实施步骤

1. 编写来源列表及脱敏失败测试。
2. 编写窗口、去重、排序和故障测试。
3. 实现仓储查询与路由。
4. 运行精确测试、检查 diff 并提交主审核。

## 9. 验收标准

1. 前端可获得稳定、去重且排序确定的来源筛选列表。
2. 没有公开文章的来源和窗口外来源不会出现。
3. feed、策略、健康、订阅和错误字段不会泄露。
4. 查询无副作用，发布库错误使用统一脱敏响应。

- 已验证列表去重、稳定排序、10 天窗口和空结果；

- 已验证所有内部来源字段被排除；
- 已检查 diff 不含敏感信息。
