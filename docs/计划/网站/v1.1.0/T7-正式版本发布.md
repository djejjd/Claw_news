## 1. 背景

用户已明确决定将已完成的 `v1.1.0` 开发计划同步为正式项目版本，不创建 GitHub Release。

## 2. 目标

将正式版本从 `0.2.1` 更新为 `1.1.0`，记录本版本公共 API 能力，完成质量检查并创建可追溯的 `v1.1.0` Git tag。

## 3. 前置依赖

- T1-T6 completed 且主审核 approved；
- 用户已明确同意版本同步、push 和创建 tag；
- 不创建 GitHub Release 或部署。

## 4. 输入与输出契约

输入：已完成的 v1.1.0 公共 API 任务及其验证记录。

输出：`pyproject.toml` 为 `1.1.0`，`CHANGELOG.md` 有对应中文记录，远端可追溯 `v1.1.0` tag；不产生 Release 或部署副作用。

## 5. 修改范围

只修改正式版本、变更记录、任务和版本计划状态；不修改任何业务行为。

## 6. 禁止事项

- 不修改 API、数据库、测试或部署配置；
- 不创建 GitHub Release；
- 不部署服务；
- 未经主审核不得提交，未经用户已给出的授权不得 push 或创建 tag。

## 7. 执行要求

- 版本计划和正式版本均使用 `v1.1.0`，本任务记录用户的统一版本决策；
- 发布前运行全量测试、lint、格式和公开边界检查；
- tag 仅指向审核后的发布提交。

## 8. 实施步骤

1. 完成独立启动审查并通过任务门禁。
2. 先更新版本号和变更记录，运行发布检查。
3. 独立主审核、任务提交和关闭记录。
4. push 审核分支，创建/合并 PR 后创建并推送 `v1.1.0` tag；不创建 GitHub Release。

## 9. 验收标准

1. `pyproject.toml` 与 `CHANGELOG.md` 均为 `v1.1.0`。
2. 完整质量检查通过，公开边界未回归。
3. tag 指向已审核发布提交，远端可解析。
4. 未创建 GitHub Release 或部署。

## 10. 检查命令

```bash
make test
make lint
./venv/bin/ruff format --check .
make check-public
```

## 11. 交付前自检

- 已确认 T1-T6 的关闭记录；
- 版本号和变更记录一致；
- 已检查 diff 无密钥和运行数据；
- tag、push 和 PR/合并结果已记录；
- 未创建 GitHub Release 或部署。

## 12. 交付格式

按仓库固定交付格式交付，并单列正式版本、tag SHA、PR 和未执行的 GitHub Release/部署。
