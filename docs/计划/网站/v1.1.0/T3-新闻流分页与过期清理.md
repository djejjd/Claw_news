## 1. 背景

公共网站需要最近 10 天的全部公开新闻，而推送去重和候选池保留规则不能代替网站新闻流。发布内容还需按长期设计在第 11 天有序清理，且清理不能被公共请求隐式触发。

## 2. 目标

实现 `GET /api/public/articles?date=&source=&page=&page_size=`，并在既有高频 ingest 调度任务结束后执行发布库过期清理。

## 3. 前置依赖

- T1 已提供公开文章读取、时区边界和 DTO；
- T2 已验证公共路由注册和统一错误转换；
- 长期设计规定清理顺序为 `expired` 标记、删除日报关联、删除文章。

## 4. 输入与输出契约

输入：可选 `date`、`source`，以及 `page`、`page_size`。

输出：

- 未传日期返回当地最近 10 个自然日的 `published` 文章；传入有效日期按当地自然日的 `fetched_at` 过滤；
- `source` 为稳定来源名；未知或无公开文章的来源返回 `200` 空列表；
- 返回 `{items, page, page_size, total}`，默认 `page=1`、`page_size=20`，范围为 `page >= 1`、`1 <= page_size <= 50`；
- 文章按有效发布时间倒序、稳定 `id` 排序；公开字段完全遵循 T1；
- 调度清理在每次高频 ingest 任务的 `finally` 分支执行。仅删除过期日报及未被保留日报引用的过期文章；顺序为标记 `expired`、删除过期日报的 `digest_items`/GitHub 推荐/日报、删除已标记文章；重复运行保持幂等。

## 5. 修改范围

1. 增加新闻流端点、查询参数校验和分页响应。
2. 为发布库增加窗口查询、总数查询和过期清理方法。
3. 在既有高频 ingest 调度入口结束后调用清理；数据库未启用时跳过，失败时记录发布库降级。
4. 增加 API、仓储和调度集成测试。

## 6. 禁止事项

- 不修改候选池的 `prune_expired` 语义或复用其结果作为发布库内容；
- 不通过新闻流查询调用清理、采集、LLM、投递或外部 HTTP；
- 不修改 `canonical_key` 去重、选材或消息状态；
- 不永久保留第 11 天以前的公共文章或日报关联。

## 7. 执行要求

- 先写新闻流、分页、日期时区和清理失败测试；
- 分页测试至少覆盖两页、并列排序、超过末页和两次状态变化；
- 清理测试必须逐步断言 `published -> expired -> 删除关联 -> 删除文章`，并再运行一次确认幂等；
- 测试同时包含应拒绝的 `page=0`/过大 `page_size` 和相邻合法值；
- 清理失败不得伪造成功、不得阻塞采集或消息投递，且不泄露数据库异常。

## 8. 实施步骤

1. 编写新闻流与分页的失败契约测试。
2. 编写跨两次清理运行的状态序列测试和调度失败测试。
3. 实现仓储查询、清理和路由。
4. 将清理接入高频 ingest 调度，验证故障隔离。
5. 运行检查、审查完整 diff。

## 9. 验收标准

1. 新闻流只展示保留窗口内的 `published` 文章，分页稳定且无重复遗漏。
2. 日期和来源筛选按约定运行，非法参数返回 `422/invalid_request`。
3. 清理顺序、两次运行幂等和保留窗口边界均有可复现测试。
4. 清理失败可观察为发布库降级，不改变采集、投递和查询语义。
5. 新闻流请求无任何写入副作用。
