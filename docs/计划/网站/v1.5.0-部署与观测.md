# v1.5.0 部署与观测开发方案

## 1. 目标、非目标与退出条件

在 `v1.0.0` 至 `v1.4.0` 功能验收后，为网站、API、数据库及既有新闻投递服务交付单实例部署、反代、持久化、备份恢复、告警、隔离端到端演练、部署验收与维护机制。

不做多实例、跨区域高可用、独立数据库集群、CDN 优化，也不改变内容生产或消息语义。退出时，所有设计约束均有代码、文档或人工证据；首次生产验收需另获用户明确批准，不能由本方案或任务审核替代。

## 2. 变更地图

| 任务 | 目标与设计章节 | 预计范围 | 验证 |
|---|---|---|---|
| T1 | Compose、反代、持久卷、迁移/备份恢复、告警（设计 4） | Compose、Docker、反代、备份/监控脚本、测试 | 构建、迁移、启动、恢复、HTTPS/端口与告警 |
| T2 | 部署前清单、分层验收、首次生产确认和回滚（设计 4） | 部署/运行文档、验收清单 | 命令与链接复核、证据字段、公开边界 |
| T3 | one-shot 隔离演练、验收配置与拒绝保护（设计 3、3.1、5、7） | 服务配置、验收 Compose、演练文档、脚本、测试 | scheduler 为零、变量隔离、失败、两次运行、生产状态不变 |
| T4 | 维护手册和周期任务（设计 6） | 维护/排障文档、待办 | 操作复核、公开边界 |
| T5 | 版本验收、文档入口与首次生产验收准备（设计 4-7） | 验收记录、文档入口、版本计划、测试证据 | 全量检查、人工演练证据 |

## 3. 依赖、顺序与并行

```text
v1.0.0 至 v1.4.0 功能验收
  -> T1 基础部署与观测
    -> T2 部署清单与验收文档 -> T5
    -> T3 隔离端到端演练 -> T5
    -> T4 维护手册与周期任务 -> T5
```

T2、T3 与 T4 可在 T1 契约稳定后并行：T2 独占部署/运行/验收清单，T3 独占演练文档与配置/状态根实现，T4 独占维护/排障文档；三者不共享允许路径。T5 在三者关闭后统一更新文档入口。T3 改动配置、持久化和外部副作用边界，必须在 T1 完成后执行；T5 必须等待所有前置任务完成并通过主审核。T3 的 secret 引用核验、验收渠道与真实消息均是人工环境证据，缺失时阻断 T5。

## 4. 集成、发布、回滚与未验证项

每个任务测试先行、独立审核和独立提交。真实验收渠道、服务器资源、生产数据库迁移和首次生产发布均属于人工环境验证；任务包必须记录执行者、时间、环境、证据位置和关闭条件。任何生产部署、合并、推送、tag 或数据恢复均需用户明确同意。
