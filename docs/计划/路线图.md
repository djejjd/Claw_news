## 已完成

- 统一 `.env` 加载，避免定时服务丢失 API 配置。
- LLM 输出补齐，保证选中的新闻不会因模型漏项而消失。
- 对 IT之家、TapTap 限制单次入选数量，并用较新的候选补位。
- 飞书推送链路和多渠道投递状态已接入。

## 当前方向

1. 继续提高来源多样性和内容命中率。
2. 用来源指标调整抓取数量和过滤档位。
3. 完善发版后验证和异常告警。
4. 逐步清理旧任务文档，保持当前入口简短。
5. 按[网站平台设计](../架构/网站平台设计.md)将项目扩展为公共新闻网站和私有运营后台。

## 网站平台阶段

- 设计阶段：完成公共日报、全部新闻流、账户、来源订阅和部署边界设计。
- 前置依赖：先落地治理 Phase 1（来源上限、摘要截断、TapTap 修复、feed 级健康基线），并在四分类契约与发布准入定型前不建立网站内容库（见[内容治理方案](内容治理方案.md)与[网站平台与内容治理协调评估说明](网站平台与内容治理协调评估说明.md)）。
- 下一阶段：按[网站开发版本计划](网站开发版本计划.md)启动 `v1.0.0`，先建立 PostgreSQL 内容发布库和 `SourceRegistryAdapter`。
- 后续阶段：依次完成 `v1.1.0` 公共只读 API、`v1.2.0` Vue 公共网站、`v1.3.0` 邀请制账户与订阅、`v1.4.0` 来源管理后台，以及 `v1.5.0` 部署与观测。

## 暂不做

- 不在没有数据证据时大幅重写评分公式。
- 不把临时来源直接设为默认正式来源。
- 不引入多实例共享状态，除非先完成存储方案设计。
- 不在四分类契约和发布准入定型前建立网站内容库。
