## 1. 背景

T2 启动时曾在未启用任务包、未确认上游关闭记录前直接进入实现准备，说明纯文字约定不能阻止流程跳步。

## 2. 目标

将任务状态、依赖、设计基线、文件边界、提交 trailer 和 PR 追溯变为可执行校验；此任务是新门禁的 bootstrap，由用户当前指令直接授权，完成后所有后续任务必须使用该门禁。

## 3. 前置依赖

无。设计基线固定为任务启动前已审核的 T1 提交；本任务不改变用户可见产品契约。

## 4. 输入与输出契约

输入：任务包 Markdown、Git 分支和差异、PR 模板中的任务包路径。

输出：

- `make task-gate TASK=<路径>` 在实施前校验任务状态、依赖、设计 SHA 和工作区文件范围；
- `make task-commit-check TASK=<路径>` 在提交前校验审核状态和暂存文件范围；
- hooks 校验 `TASK_PATH` 和 `Task: <任务编号>`；CI 重新校验 PR 声明的一个或多个任务包；启动门禁还要求独立启动审查结论。

## 5. 修改范围

新增 Python 标准库门禁脚本、其单元测试和 Git hooks；更新 Makefile、CI、PR 模板、开发流程、文档模板、文档状态说明和仓库公共契约。

## 6. 禁止事项

不修改业务代码、正式版本号、变更记录、发布逻辑或现有 v1.1.0 任务状态；不自动执行 `make install-hooks`，避免隐式修改开发者 Git 配置。

## 7. 执行要求

脚本测试先行；路径和任务号不允许推断；失败必须非零退出并说明原因。bootstrap 提交仍使用现有人工 diff 审核，不能宣称已由尚未安装的 hook 拦截。

## 8. 实施步骤

1. 增加门禁脚本和解析/路径边界失败测试。
2. 增加 Make、hooks、CI 和 PR 入口。
3. 同步状态机和任务包模板。
4. 运行单测、完整测试、lint、格式和公开边界检查，提交主审核。

## 9. 验收标准

1. 缺少精确允许路径、设计 SHA、有效状态或完成依赖的任务不能通过开始门禁。
2. 范围外工作区或暂存改动不能通过对应门禁。
3. PR 缺少任务包字段或含范围外改动时 CI 失败。
4. 文档明确任务状态机和 bootstrap 例外边界。
