## 1. 背景

v1.2.0 发布 PR 同时携带多个已完成任务的实现、关闭记录和版本文件。现有 CI 将 PR 相对目标分支的全部路径交给每个任务包的允许路径校验；当 PR 是多个任务的集成或发布 PR 时，历史任务文档、版本文件和构建入口会被单个任务包误判为范围外改动，造成门禁误报。该问题不影响业务代码，但会降低 CI 对真正范围外改动的区分能力。

## 2. 目标

- 为多任务功能 PR 提供可验证的任务路径并集校验，并保留每个任务提交必须属于当前 PR 的约束。
- 为发布 PR 提供显式、可追溯的发布模式：发布任务只校验其发布增量；已在目标分支关闭的功能任务不被重复纳入发布 PR 的实现范围校验。
- 对缺少模式、任务包未完成、任务提交不在当前 PR、发布任务修改业务路径等情况继续失败。

非目标：不放宽任务状态、设计基线、依赖关闭、启动审查、主审核、分支或敏感文件校验；不修改任何业务功能和已发布 tag。

## 3. 前置依赖

- `v0.2.2-T1` 已完成且主审核结论为 `approved`。
- 发布 PR 与多任务 PR 的行为契约已在 v1.2.1 方案中批准；启动审查只确认依赖、文件边界、分支/worktree 和实施前置，不替代设计批准。
- 当前工作必须位于独立分支或 worktree，且不得在 `main` 上实施。

## 4. 任务输入、交付物与行为契约

输入：PR 正文中的任务包列表和门禁模式、目标分支、当前 PR 相对目标分支的路径差异、各任务包元数据。

交付物：任务门禁脚本、单元测试、CI 调用参数和中文流程说明。

行为契约：

| 模式 | 输入要求 | 路径校验 | 任务提交校验 | 失败语义 |
|---|---|---|---|---|
| `常规任务` | 至少一个 `active`/`completed` 任务包；CI 中必须为 `completed` | 所有声明任务允许路径与任务包路径的并集 | 每个任务提交必须存在于当前 PR，不能已在目标分支关闭 | 任一任务状态、依赖、提交或路径不符即失败 |
| `发布 PR` | 一个且仅一个 `completed` 且 `任务类型：发布` 的任务包 | 只校验发布任务的增量允许路径、任务包和版本计划路径；不得包含业务实现路径 | 发布任务提交必须在当前 PR；历史功能任务仅作为依赖证据，不重复校验其实现提交 | 缺少发布模式、多个发布任务、类型不匹配、版本/业务路径混入即失败 |

发布模式必须由 CI 从 PR 正文读取，不能通过分支名、环境变量或隐式文件名推断。任务包元信息的 `任务类型` 合法值为 `常规` 或 `发布`；本 T1 为 `常规`，未来版本发布任务必须显式声明 `发布`。当前 PR 声明任务缺失类型直接失败；只有任务提交 SHA 已是目标分支祖先、且任务未作为当前 PR 声明任务时，历史缺失类型才兼容解释为 `常规`，未知或重复类型仍失败。`门禁模式：常规任务` 只能包含常规任务；`门禁模式：发布 PR` 必须包含且仅包含一个 `任务类型：发布` 的已完成任务。模式字段缺失、未知、重复，或任务类型与模式不匹配，必须失败。

## 6. 禁止事项

- 不以 `--allow-all`、环境变量、分支名或通配路径绕过范围校验。
- 不把发布 PR 默认视为通过；发布任务仍需完成状态、依赖、设计基线、启动审查、主审核和提交 trailer 校验。
- 不把已在目标分支关闭的任务重新标记为当前 PR 任务，也不删除历史任务提交校验逻辑。
- 不修改业务代码、正式版本、变更记录、部署配置或已发布 tag。

## 7. 执行要求

测试先行。先增加会在现有实现上失败的发布 PR、多任务 PR 和反向拒绝测试，再实现最小解析与分支逻辑。新增模式匹配必须同时测试应拒绝的相近值（如 `发布PR`、`发布-PR`、未知模式）和合法常规值；路径过滤必须同时测试合法发布文件与业务文件误放行。

复杂的模式分流、历史任务追溯和错误转换需添加中文定向注释，解释为何不重复校验已关闭任务以及为何拒绝隐式降级。

## 9. 验收标准

1. v1.2.0 类发布 PR 的版本文件和发布记录不会被历史功能任务的允许路径误判；发布 PR 混入任一业务实现文件时失败。
2. 两个以上任务包的常规 PR 仅在路径属于声明任务并集、且各任务提交都在当前 PR 时通过。
3. 缺少/未知/重复门禁模式、任务类型未知/重复、当前 PR 声明任务类型缺失、模式与任务类型不匹配、重复任务包、任务未完成、依赖未关闭、提交不在 PR 或已在目标分支关闭时均失败；仅祖先且未声明的历史任务缺失类型按常规兼容。
4. PR 模板包含且仅包含可解析的 `门禁模式：常规任务` 或 `门禁模式：发布 PR` 字段；正文解析与 CI 参数保持一致。
5. 本 T1 任务类型为 `常规`，不得被 `发布 PR` 模式误识别为发布任务；未来发布任务必须显式为 `任务类型：发布`。
6. begin/commit 行为和现有历史任务豁免保持不变。
7. 新增测试覆盖正常、边界、失败和最可能的反向回归，且完整测试、lint、格式和公开边界检查通过。
