## 推送渠道

飞书、企业微信和 Telegram 都是可选渠道。渠道配置成对校验：飞书需要 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_CHAT_ID`；Telegram 需要 token 和 chat ID；企业微信使用 `WECOM_WEBHOOK_URL`。

未配置的渠道不会创建投递任务。一次发布可以同时投递多个已启用渠道，单个渠道失败会记录自己的状态。

## 发布结果

发布流程会保存摘要、发布状态和待投递消息。常见状态为 `ok`、`degraded`、`failed` 和 `skipped`。`degraded` 表示部分来源或状态保存异常，但已有渠道可能已经成功推送。

## 故障恢复

投递状态按渠道保存。飞书或 Telegram 的待投递记录会在后续运行中尝试恢复；仅企业微信配置时不走这条 pending 恢复路径。服务异常时，如果配置了企业微信，会尝试发送错误通知；错误通知失败只写日志，不覆盖原始故障。

## 配置来源

配置统一来自项目根目录 `.env`，显式进程环境变量优先。真实密钥只存在运行环境，不能写入文档或提交到 Git。
