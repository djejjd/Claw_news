## 数据流

```text
定时任务或 HTTP
  -> 采集器
  -> 候选池与去重
  -> 相关性过滤和四阶段选材
  -> LLM 结构化摘要（可选相关性淘汰与全池补位）
  -> 飞书 / 企业微信 / Telegram
  -> digest、发布状态和投递状态落盘
```

## 主要模块

- `app/scheduler/`：注册 09:00 发布和高频采集任务。
- `app/ingest/`、`collectors/`：按来源采集并写入候选池。
- `app/pipeline/selection.py`：按分类、时间和来源上限选材，并在 LLM 淘汰后从全候选池重选。
- `app/tools/llm.py`：调用 OpenAI-compatible API，补齐模型漏掉的条目，并对启用的相关性复核保留逐 URL 输出。
- `app/pipeline/news_pipeline.py`：编排选材、单次摘要调用、相关性淘汰、渲染、推送和状态保存。
- `app/config.py`：加载根目录 `.env`，进程环境变量优先。
- `app/storage/`、`app/delivery/`、`infra/storage/`：保存候选、摘要、来源指标和多渠道投递状态。

相关性复核的审计字段只写入内部 digest、pending delivery 和 publish-status；公开 API 对未知字段保持忽略。来源采集调节使用 L2 初选计数 `selection_eligible_count / accepted_count`，最终发布条数仅写入独立 publish metrics，避免聚合或 LLM 淘汰影响抓取调节。

## 服务边界

服务是单实例进程，状态保存在本地 `data/`。`GET /health` 查看服务和来源状态，`POST /run/news` 手动触发一次发布。部署、配置和运行状态不依赖服务器直接访问 GitHub。
