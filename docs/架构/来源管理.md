## 当前来源

- AI：HuggingFace Daily Papers、量子位及配置的 AI RSS。
- 工具：GitHub 项目快照和工具类 RSS。
- 游戏：TapTap 下载榜、游研社及其他游戏 RSS。
- 数码内容：IT之家、少数派等 RSS，运行时按数码类展示。IT之家等综合快讯来源可配置 `dynamic_category: true`，在发布与回放时按内容重分类；默认分类仅作未命中时的兜底。

实际来源由 `collectors/ai_rss.py`、`app/ingest/source_registry.py` 和运行时 feeds 配置共同决定。

运行时有效 RSS 配置以代码默认来源为基线，本地 `feeds.yaml` 中相同 `source` 的字段覆盖默认值，新增本地 `source` 会追加。该迁移策略确保已挂载的旧配置不会遗漏后续版本新增来源；旧 `tool/ithome` 会规范化为 `digital/ithome` 并继承动态分类开关。

Phase 2 新增 OSCHINA、V2EX 技术节点、Hacker News、cnBeta、9to5Mac、TechCrunch、GamesIndustry、Nintendo Life、InfoQ、Hugging Face Blog 与 arXiv 两个分区。国外来源依赖部署环境的网络/代理条件；V2EX 与 cnBeta 使用 `fast_news`、24 小时保留和单次 2 条上限。

## 来源策略

每个来源可以配置层级、保留时长、质量权重、过滤档位和单次入选上限。`fast_news` 来源单次最多 2 条且不可突破；其他来源默认最多 3 条，仅摘要总量不足时允许突破并写入选材降级证据。RSS 来源写在 `feeds` 下，TapTap 等非 RSS 来源写在 `source_policies` 下；两类策略都会进入正式选材。来源失败由单源隔离逻辑记录，不应阻断其他来源。

采集状态保留最近成功/失败时间、连续失败次数和失败摘要。连续失败次数达到 `SOURCE_FAILURE_DEGRADED_THRESHOLD`（默认 3）后，`/health` 将来源标为 `degraded`；RSS 的单个 feed 失败独立写入指标，不能覆盖整个 RSS 聚合来源的状态。

## 新增来源

先验证可达性、更新频率、内容质量和分类归属，再加入正式配置。临时试验源放在本地配置或 `docs/研究/` 记录中，不直接写进正式来源列表。TapTap 等榜单来源必须提供非空的条目说明，才能进入候选池。

## 已知限制

国外来源可能受网络、代理或 API 限流影响。HuggingFace 可通过 `HF_OPTIONAL=1` 降级为跳过；来源指标写入异常会记录为非阻塞错误，当前待后续治理。
