# 公共网站前端设计

## 1. 背景与目标

`v1.1.0` 已提供只读公共内容 API；`v1.2.0` 只建立未登录访客的浏览界面。前端独立构建为 Vue 3 + TypeScript 静态资源，唯一内容来源为 `/api/public`，不得读取候选池、JSON 审计、模拟运行时数据，也不得触发采集、摘要或投递。

目标是让访客浏览当天日报、最近十天新闻并按来源筛选。登录、订阅、收藏、已读、推荐、正文抓取、管理页面、生产反代和部署均不在本设计范围。

## 3. 路由与页面状态

| 路由 | 页面 | 查询参数 | 数据请求 | 成功状态 | 空状态 | 失败状态 |
|---|---|---|---|---|---|---|
| `/` | 公共日报首页 | 无 | `GET /api/public/digests` | 显示日期、日报判断、按 `position` 排列的日报项及 GitHub 推荐 | `404/digest_not_found` 显示“暂无日报” | `503`、网络故障或未知响应显示可重试错误 |
| `/articles` | 最近十天新闻流 | `source?: string`、`page?: positive integer` | `GET /api/public/sources`；`GET /api/public/articles?source=&page=` | 显示 API 返回顺序的文章与分页 | 空 `items` 显示“暂无新闻” | `422`、`503`、网络故障或未知响应显示可重试错误 |

- 顶部导航只提供“日报”和“新闻”；首页为 `/`，新闻页为 `/articles`。
- 默认新闻请求不传 `source` 与 `page`，由 API 使用最近十天窗口和第 1 页默认值；本版本不提供日期筛选 UI。
- 用户选择来源时，更新 URL 的 `source` 并删除 `page`，随后请求第 1 页；翻页只更新 `page`。无效 URL 参数在客户端归一为默认值，不向 API 发送非法页码。
- 请求开始时保留页面骨架加载态，但不得把上一次筛选或页码的文章伪装为当前结果。重试仅重新发起当前 URL 对应的只读请求。

## 4. 数据、可见性与外链

前端 DTO 严格采用《公共内容 API 设计》：文章可显示 `title`、`category`、`topic`、`summary`、`published_at`、`fetched_at` 和嵌套来源公开字段；日报项额外显示 `core_summary`、`importance`、`trend`、`topic_label`；GitHub 推荐显示 `full_name` 与 `recommendation`。

不显示或持久化 `canonical_key`、`visibility`、评分、`relevance`、来源 feed/健康状态、运行错误、认证信息或任意内部候选字段。空 `summary` 或 `topic` 直接省略对应展示，不抓取正文或补造文本。

`original_url` 是唯一文章外链，使用新标签页打开并设置 `rel="noopener noreferrer"`；`site_url` 仅在存在时作为来源站点外链，同样使用该安全属性。

## 5. 响应式与可访问性

- 宽度不低于 768px 时使用内容区和稳定导航；低于 768px 时内容单列、筛选控件换行，分页按钮保持可触达。
- 文章、日报项和错误区域使用语义化标题、列表、按钮和链接；加载、空与失败状态应有可读文本与 `aria-live` 通知。
- 标题、来源、摘要和 URL 过长时允许换行，不截断到不可读；不得有文字遮挡、重叠、不可点击控件或仅靠颜色表达状态。

## 6. 工程、代理与持续验证

- 固定 Node.js `22.x` 和 npm `10.x`；使用 `package-lock.json`，CI 仅使用 `npm ci`。
- 前端位于 `frontend/`，使用 Vue 3、TypeScript、Vite、Vue Router、Vitest 与 Playwright。前端脚本固定为 `lint`、`typecheck`、`test`、`build`、`e2e`；根目录 `make frontend-check` 依次执行 lint、类型检查、单元测试和构建，`make frontend-e2e` 仅执行浏览器 E2E。两者均假定已先执行 `npm ci`，不隐式安装依赖。
- 开发和浏览器测试使用 Vite 代理 `/api` 到显式的本地目标地址，浏览器不配置 CORS，也不使用 Cookie 或凭证。生产反代留给 `v1.5.0`。
- CI 安装 Node 22、执行 `npm ci`、lint、类型检查、单元测试、构建，并安装 Chromium 后执行 Playwright；Python 既有检查保持不变。

## 7. 隔离真实 API E2E

T1 新增仅供测试的 Python HTTP 服务：它创建临时 SQLite 发布库，使用既有 `PublicationStore` 写入固定的 `published` 文章、日报和来源，并将既有 `app.publication.routes.router` 注册到临时 FastAPI 应用。该服务运行在临时端口，绝不导入 `app.main`，因此不会启动 APScheduler、采集、LLM、投递或写入项目 `data/`。

Playwright 通过 Vite 代理访问该服务，验证的仍是实际公共路由、DTO 映射、查询与错误语义，而非浏览器 mock。测试服务须提供成功、空日报、空文章、`503` 与网络断开场景；固定 `TZ=UTC`、测试日期和数据库种子，使十天窗口与分页可复现。

## 8. 验收与非目标

桌面和移动视口均须完成：首页日报浏览、跳转新闻页、来源筛选、分页、文章原文外链，以及加载、空、失败和重试。E2E 断言 URL 查询参数、API 请求参数、可见内容与错误状态，且至少覆盖两次来源或分页变化。

本设计不改变公共 API、FastAPI 生产启动方式、调度、发布库 schema 或任何生产部署配置。真实生产数据库、域名、反代、HTTPS 和缓存不作为 `v1.2.0` 验收证据。
