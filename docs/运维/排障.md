# 巡检与排障

## 日常巡检

```bash
curl -sS http://127.0.0.1:8000/health | python3 -m json.tool
```

重点看 `status`、`ingest_fresh`、`last_publish` 和 `sources`。`failed` 需要排查，`degraded` 先确认是否只是可选来源异常。检查最新 `ai_digest.json`，确认总条数接近 10 条、分类没有长期缺失、单个高频来源没有占据大多数。

需要复核选材时使用只读回放：

```bash
./venv/bin/python scripts/replay-content-selection.py \
  --data-dir data --at '<检查时间，含时区>' --format json
```

不要提交生产 `data/`、候选原文、运行时 feeds 或凭据。

## 没有收到推送

```bash
cat data/publish_status.json | python3 -m json.tool
curl -sS http://127.0.0.1:8000/health | python3 -m json.tool
```

`failed` 重点看 `errors` 和渠道状态；`skipped` 通常表示候选为空或已被跨次去重；未配置渠道时不会发送。飞书或 Telegram 的 pending 记录会在后续运行尝试恢复，只有企业微信时不走这条路径。

## 条数少、来源单一或配置错误

检查 `ai_digest.json` 和候选池，回放查看 `source_distribution`、`category_distribution`、`backfill_count` 和拒绝原因。IT之家、TapTap 单次最多 3 条，候选不足时无法凭空补足。

确认服务目录存在 `.env`，变量名与 `.env.example` 一致、权限为 `600`，然后运行 `make check-config`。进程环境变量会覆盖 `.env`，修改后需重启容器或服务。

## 服务异常

```bash
docker logs claw-news --tail 50
```

区分来源失败、LLM 请求失败和渠道推送失败。单个来源失败不应阻断其他来源；缺少三个 LLM 配置会阻止服务启动。
