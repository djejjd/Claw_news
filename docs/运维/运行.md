# 运行与验证

## 本地运行

```bash
make install
cp .env.example .env
make check-config
make test
make dry-run
```

启动检查只要求 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`。实际发布还需至少配置一个渠道；飞书、Telegram 参数必须成组填写，企业微信填写 `WECOM_WEBHOOK_URL`。

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
curl -sS http://127.0.0.1:8000/health
curl -sS -X POST http://127.0.0.1:8000/run/news
```

`dry-run` 不触发真实 LLM 摘要和推送。

## 定时方式

服务模式内置 APScheduler：每天 09:00 发布，每 30 分钟刷新候选池，时区由 `TZ` 控制，默认 `Asia/Shanghai`。服务保持单实例运行。

也可以关闭内部 scheduler，改用外部计时器调用 `POST /run/news`。两种方式只能选一种，不要与 cron、systemd timer 或 macOS launchd 并行。

launchd 仅用于本地或旧 CLI 兼容入口。使用模板前复制文件并将 `{{PROJECT_DIR}}` 替换为本机项目路径；launchd 不读取交互式 shell 变量，项目根目录 `.env` 是唯一运行配置文件。

## 发版后验证

```bash
docker ps --format '{{.Names}} {{.Status}}' | grep claw-news
curl -sS http://127.0.0.1:8000/health | python3 -m json.tool
curl -sS -X POST http://127.0.0.1:8000/run/news | python3 -m json.tool
```

确认容器持续运行，`health.status` 为 `healthy` 或 `degraded`，手动发布结果不为 `failed`。检查 `data/` 中最新摘要的条数、分类、来源和原文链接；指标写入异常记录在 `errors` 中。
