# 服务器部署

生产环境使用 Docker Compose。公开仓库不保存服务器地址、账号或私有发布脚本；可基于 `deploy.example.sh` 在本地维护部署入口。同步代码时不要包含 `.env` 和 `data/`。

```bash
make lint
make test
docker compose up -d --build
```

部署后检查 `/health`。启动检查只强制三个 LLM 配置；要成功发布还需至少配置一个推送渠道。

## Phase 2 来源配置迁移

容器会将项目根目录未入库的 `feeds.yaml` 只读挂载为运行配置。Phase 2 起，运行时以受版本控制的默认来源为基线，再以本地同名 `source` 覆盖；未在本地声明的新增来源会自动保留。历史配置中的 `tool/ithome` 会迁移为 `digital/ithome`，并继承 `dynamic_category: true`，避免重复抓取且让综合快讯可以按内容重分类。建议将本地配置同步为 `feeds.example.yaml` 的四分类结构，尤其不要再在 `tool` 段保留 `ithome`。

`.env` 示例：

```dotenv
LLM_API_KEY=真实密钥
LLM_BASE_URL=https://api.example.com/v1
LLM_MODEL=模型名称
FEISHU_APP_ID=可选
FEISHU_APP_SECRET=可选
FEISHU_CHAT_ID=可选
TELEGRAM_BOT_TOKEN=可选
TELEGRAM_CHAT_ID=可选
WECOM_WEBHOOK_URL=可选
```

飞书三个参数必须一起填写，Telegram 的 token 和 chat ID 也必须一起填写。`.env` 权限应为 `600`。

如果服务器访问 GitHub 不稳定，不要把服务器 `git pull` 作为主要路径；在本地通过私有脚本或 CI 同步构建产物。部署完成后按 [运行与验证](运行.md) 检查服务和实际推送。
