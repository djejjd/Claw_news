# 开发文档模板

## 领域设计骨架

```text
front matter：状态、批准角色、批准日期、Git commit SHA 基线、待决问题
1. 背景与目标 / 非目标
2. 决策与批准
3. 资源、状态与可见性
4. 接口变更表（方法、路径、调用者、认证、参数、返回、错误、兼容性）
5. DTO 字段映射（类型、可空、来源、公开性）
6. 成功/失败 JSON 与错误副作用表
7. 数据、时间、并发、清理与安全语义
8. 兼容性、测试场景、修订记录
```

## 版本开发方案骨架

```text
front matter：状态、引用的 approved 设计 SHA、版本、待决问题
1. 目标、非目标、退出条件
2. 变更地图：端点/模块/存储/配置/调度 -> 设计章节 -> 任务 -> 文件 -> 测试
3. 任务依赖与并行限制
4. 集成、发布、回滚与未验证事项
```

## 原子任务包骨架

```text
任务元信息：编号、依赖、允许并行、文件边界、完成状态、引用设计 SHA
1. 背景
2. 目标
3. 前置依赖
4. 任务输入、交付物与行为契约
5. 修改范围与接口变更表
6. 禁止事项
7. 执行要求
8. 实施步骤
9. 验收标准
10. 检查命令
11. 交付前自检
12. 交付格式
```

接口变更表必须覆盖新增、修改和保持不变项；列出参数、返回、错误、兼容性、读写副作用和测试文件。每个任务的测试矩阵必须包含正常、边界、失败与反向回归。
